# Sub2API 精简 Cloudflare 部署计划

## 目标
基于现有 Sub2API 的核心网关逻辑，精简为可在 Cloudflare Pages + Functions 上运行的聚合网关，保留分组/渠道切换、API Key 分发、OpenAI/Claude/Grok 路由、Token 计费与基于错误率+错误数的无感故障切换。

---

## 一、部署架构
```
Cloudflare Pages（前端静态资源 + Functions API）
├── 前端：Vue3 精简版（保留现有样式，删除不需要的页面）
└── Functions：TypeScript 网关核心（替代 Go 后端）
    ├── D1（SQLite）：持久化存储
    └── KV：配置缓存
```

## 二、数据存储（D1 Schema）
```sql
-- 管理员（仅你一人）
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  created_at TEXT DEFAULT (datetime('now'))
);

-- 分组
CREATE TABLE groups (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  description TEXT,
  enabled INTEGER DEFAULT 1,
  priority INTEGER DEFAULT 0,
  error_threshold REAL DEFAULT 0.5,
  error_count_threshold INTEGER DEFAULT 5,
  window_seconds INTEGER DEFAULT 300,
  created_at TEXT DEFAULT (datetime('now'))
);

-- 渠道
CREATE TABLE channels (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  provider TEXT NOT NULL,
  base_url TEXT,
  api_key TEXT,
  enabled INTEGER DEFAULT 1,
  priority INTEGER DEFAULT 0,
  error_count INTEGER DEFAULT 0,
  error_rate REAL DEFAULT 0,
  last_error_at TEXT,
  created_at TEXT DEFAULT (datetime('now'))
);

-- 上游账号
CREATE TABLE accounts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  provider TEXT NOT NULL CHECK(provider IN ('openai','anthropic','xai')),
  api_key TEXT NOT NULL,
  base_url TEXT,
  group_id INTEGER NOT NULL,
  channel_id INTEGER NOT NULL,
  enabled INTEGER DEFAULT 1,
  error_count INTEGER DEFAULT 0,
  error_rate REAL DEFAULT 0,
  last_error_at TEXT,
  last_error_msg TEXT,
  priority INTEGER DEFAULT 0,
  created_at TEXT DEFAULT (datetime('now'))
);

-- 模型映射
CREATE TABLE model_mappings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  requested_model TEXT NOT NULL,
  provider TEXT NOT NULL,
  upstream_model TEXT NOT NULL,
  group_id INTEGER NOT NULL,
  enabled INTEGER DEFAULT 1,
  priority INTEGER DEFAULT 0
);

-- API Key
CREATE TABLE api_keys (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  key_hash TEXT NOT NULL UNIQUE,
  name TEXT,
  enabled INTEGER DEFAULT 1,
  balance REAL DEFAULT 0,
  quota_limit REAL DEFAULT 0,
  created_at TEXT DEFAULT (datetime('now'))
);

-- 使用记录
CREATE TABLE usage_records (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  api_key_id INTEGER,
  model TEXT NOT NULL,
  provider TEXT NOT NULL,
  prompt_tokens INTEGER DEFAULT 0,
  completion_tokens INTEGER DEFAULT 0,
  total_tokens INTEGER DEFAULT 0,
  cost REAL DEFAULT 0,
  status INTEGER DEFAULT 200,
  error_message TEXT,
  latency_ms INTEGER,
  created_at TEXT DEFAULT (datetime('now'))
);

-- 请求日志（用于错误统计）
CREATE TABLE request_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id INTEGER NOT NULL,
  channel_id INTEGER NOT NULL,
  group_id INTEGER NOT NULL,
  model TEXT NOT NULL,
  status INTEGER NOT NULL,
  error_message TEXT,
  latency_ms INTEGER,
  created_at TEXT DEFAULT (datetime('now'))
);
CREATE INDEX idx_req_logs_account_created ON request_logs(account_id, created_at);
CREATE INDEX idx_req_logs_channel_created ON request_logs(channel_id, created_at);
CREATE INDEX idx_req_logs_group_created ON request_logs(group_id, created_at);
```

## 五、核心功能实现细节

### 1. 密码登录
- 单用户（你），密码 bcrypt 哈希存储在 D1
- JWT Token 或 Session Cookie（Cloudflare KV 存储 session）
- 无注册、无 OAuth、无 TOTP

### 2. API Key 认证
- 用户生成 API Key，存储 SHA256 哈希
- 网关请求头 `Authorization: Bearer <key>` 认证
- 支持多 Key 管理（启用/禁用、余额查询）

### 3. 路由转发
- OpenAI Chat Completions：直接转发到上游 `/v1/chat/completions`
- OpenAI Responses API：直接转发到上游 `/v1/responses`
- Claude Messages：转发到上游 `/v1/messages`，添加 `anthropic-beta` 头
- Grok：OpenAI 兼容，转发到上游 `/v1/chat/completions`
- 模型映射：根据分组配置，将请求模型映射到上游模型

### 4. 故障切换（基于现有项目逻辑）
- 继承现有的 failover loop 策略：
  - 同账号重试：瞬态错误在同账号重试最多 3 次
  - 账号切换：重试耗尽后切换到下一个可用账号
- **新增**：错误率 + 错误数统计
  - 每个账号/渠道维护滑动窗口（默认 5 分钟）内的错误计数和总请求数
  - 错误率 = 错误数 / 总请求数
  - 当错误率 > 阈值（如 50%）或错误数 > 阈值（如 5 次）时，标记账号为不可用
  - 自动切换到下一个可用账号，实现无感切换
- 错误统计存储：
  - 内存中维护滑动窗口（用于实时决策）
  - 定期写入 D1 `request_logs`（用于持久化和审计）

### 5. Token 计费
- 简单计费：根据模型和平台计算 cost
- 记录到 `usage_records` 表
- 用户余额扣减（你不需要多用户，可简化或省略）

### 6. 配置管理
- 分组、渠道、账号、模型映射通过前端页面 CRUD
- 配置变更后写入 D1，同时更新 KV 缓存
- Worker 优先从 KV 读取配置，KV  miss 时从 D1 加载
